ProLaptop Client

Trang quản trị chạy như thế nào

Đây là web dành riêng cho admin của cửa hàng: xem doanh thu, quản lý sản phẩm, hãng, người dùng, đơn hàng, đánh giá và chat với khách. Khách mua hàng dùng app mobile, không dùng trang này. Viết bằng React 18 (chạy bằng Vite), giao diện dùng thư viện Ant Design, gọi server NestJS qua axios.

StateuseState

Dữ liệu component tự giữ và có thể thay đổi: danh sách đang hiển thị, ô tìm kiếm, đang loading… Gọi hàm set… để đổi state, React sẽ vẽ lại component với giá trị mới.

const [reviews, setReviews] = useState([]);
setReviews(data); // → giao diện tự cập nhật
EffectuseEffect

Đoạn code chạy sau khi giao diện đã vẽ, dùng cho việc ngoài giao diện: gọi API, kết nối socket, đọc localStorage. Mảng cuối ([]) quyết định khi nào chạy lại.

useEffect(() => { fetchReviews(); }, []);
// [] = chỉ chạy 1 lần khi màn hình mở
// [search] = chạy lại mỗi khi search đổi
Hookhooks/adminAuth.jsx

Hàm bắt đầu bằng use…, cho component "móc" vào tính năng của React. useState, useEffect là hook có sẵn. Có thể tự viết hook để dùng lại logic, ví dụ useAuth().

const useAuth = () => useContext(AccountContext);

Luật: chỉ gọi hook ở đầu component, không gọi trong if hay vòng lặp.

Contextcontext/accountContext.jsx

Kho dữ liệu dùng chung cho cả cây component, khỏi phải truyền props qua từng tầng. Provider bọc ngoài cùng; component nào cần thì đọc bằng useContext.

<AccountContext.Provider value={{ token, account }}>
  {children}
</AccountContext.Provider>
// ở bất kỳ đâu bên trong:
const { account } = useContext(AccountContext);

Vòng đời một thao tác

Một cú bấm đi qua những đâu

Chọn một ví dụ. Mỗi thao tác của admin đi qua cùng một chuỗi bước, từ giao diện tới server rồi quay về giao diện. Bước sáng là bước được chạy, bước mờ là bị bỏ qua.

    Chuỗi này giống Request Lifecycle bên server, nhưng nhìn từ phía trình duyệt: bước Server chính là toàn bộ Middleware → Guard → Pipe → Controller → Service → Database đã mô tả trong tài liệu server.

    Các luồng chính

    Từng tính năng chạy ra sao

    Sắp theo thứ tự admin thường dùng: đăng nhập trước, rồi xem tổng quan, rồi quản lý từng loại dữ liệu. Mọi URL có tiền tố /api. Sơ đồ đọc từ trên xuống theo thời gian.

    Cần lưu ý

    Những điểm nên biết trước khi sửa code

    1
    File src/.env không được đọc

    Vite chỉ đọc .env ở thư mục gốc ProLaptop-client/. App vẫn chạy nhờ giá trị mặc định http://localhost:5003 trong config/env.js; muốn đổi server thì tạo .env.development / .env.production ở thư mục gốc.

    2
    Token gần như không được gửi lên

    Hầu hết file API dùng applicationNoAuth hoặc formData, không kèm token. Đăng nhập cũng không gọi setToken, nên token chỉ được gắn vào axios sau khi tải lại trang.

    3
    Chỉ chặn ở giao diện

    Khung admin chỉ kiểm tra "có token hay không", không kiểm tra role hay hạn token, cũng không xử lý lỗi 401. Server cũng không bảo vệ các route admin, nên ai biết URL vẫn gọi được.

    4
    localStorage lưu cả mật khẩu đã mã hoá

    account là toàn bộ response đăng nhập, gồm cả trường password. Sửa hồ sơ chỉ cập nhật context, không cập nhật localStorage, nên tải lại trang sẽ thấy thông tin cũ.

    5
    Chat còn nhiều lỗi

    ID admin ghi cứng trong chat.jsx và messagesApi.jsx. Tin admin đã gửi bị lọc mất khi tải lịch sử. Tin mới không lọc theo người đang chat. Đóng khung chat ngắt luôn socket của danh sách chat.

    6
    Code thừa

    React Query đã bọc nhưng không dùng, loginGgApi không ai gọi, modal "Add User" không bao giờ mở, index.css và src/assets/ không được import.
